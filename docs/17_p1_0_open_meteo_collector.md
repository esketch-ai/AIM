## 1. 의사결정 배경: 왜 이 소스인가

문서 14는 기상청 인증키가 승인 대기 중이라 기상 실측을 P1-0으로 미뤘습니다.
사용자께서 "구글지도와 기상자료 오픈형을 사용해도 되고"라고 하셨고, 조사한 결과는 이렇습니다.

| 항목 | 기상청 통합데이터 | **Open-Meteo** | Google Maps Geocoding |
| :--- | :--- | :--- | :--- |
| 키·가입 | 승인 대기 중 | ✅ **불필요** | 카드 + 계좌 정산 필수 |
| 즉시 사용 | ❌ | ✅ | 크레딧카드 필요 |
| 상업적 이용 | ✅ 무료 | 🔴 **무료 티어 비상업 전용** | 유료 |
| 국내 정밀도 | 최상 | KMA 모델 포함(1.5~13km) | 해당 없음 |
| 격자 좌표 변환 | 필요 | **불필요**(위경도 그대로) | 불필요 |

**Google Maps는 현 단계에서 불필요**로 판단했습니다. 좌표 변환은 기상청 격자 변환이나
무료 지오코딩으로 해결되며, 크레딧카드 대기를 만드는 것만 남습니다.
경쟁사 레이더(P2)에 필요해질 때 다시 검토합니다.

### 1.1 상업 라이선스 — 이 비용은 숨기지 않는다

Open-Meteo 약관 원문:

> *"You may only use the free API services for non-commercial purposes."*

**AIM은 월 49,000원~199,000원을 받는 유료 SaaS입니다.** 무료 티어로 사장님에게 발송할
카피를 만들면 라이선스 위반입니다. 상업 구독이 필요하며, 이 판단을 **문서만이 아니라
코드로** 막았습니다.

```python
# aim/open_meteo_collector.py
def assert_commercial_use(api_key, endpoint):
    if endpoint == COMMERCIAL_ENDPOINT and not api_key:
        raise CommercialLicenceRequired(...)
```

무료 엔드포인트는 차단하지 않습니다(테스트·시연용으로 필요하므로). 다만 상업 엔드포인트는
키 없이는 아예 호출되지 않습니다. **시도 한 번이면 이미 위반이므로 예외로 여기서 막습니다.**

## 2. 구현 중 발견한 실제 버그: 기상 코드 체계 충돌

P0-3에서 만든 매핑표는 **기상청 SKY 코드(0~9)** 기준이었습니다.
Open-Meteo가 돌려주는 건 **WMO 코드(0~99)**입니다. 그리고 두 체계는 **숫자가 겹칩니다.**

| 코드 | KMA SKY | WMO |
| :--- | :--- | :--- |
| 0 | 맑음 | Clear sky ✅ 일치 |
| 3 | 흐림 | Overcast ✅ 일치 |
| **4** | **약한 비** | **(없음 — 45가 안개)** |
| **6** | **눈 또는 비** | **(없음)** |
| **45** | **(없음)** | **안개** |
| **61** | **(없음)** | **약한 비** |
| **95** | **(없음)** | **천둥번개** |

### 2.1 그대로 썼을 때의 실패

```
WMO 61 (약한 비) → KMA 표에 '61' 없음 → 라벨 조용히 사라짐
WMO 95 (천둥)   → KMA 표에 '95' 없음 → 라벨 조용히 사라짐
KMA 4 를 WMO로 오인 → 맑은 날에 비라서 broadcast
```

가장 나쁜 시나리오는 첫 번째입니다. **비가 포함된 코드가 표에 없어 조용히 사라지면**,
강수확률 폴백만 남습니다. 그러면 "강수확률 30% + 천둥" 같은 진짜 위험 신호를 놓칩니다.
표에 없다는 이유로 사라진 코드는 **"우리가 몰랐다"가 아니라 "우리가 놓쳤다"**입니다.

### 2.2 해결: 체계를 명시하고 추측하지 않는다

스키마에 `weather_code_system`을 추가하고, 라벨 해석은 명시된 체계로만 합니다.

```python
weather_code: Optional[str]         # 원값
weather_code_system: Optional[str]  # 'KMA_SKY' 또는 'WMO'
```

- 체계가 없거나 미지원이면 라벨을 **지어내지 않고 None**을 반환
- 강수확률처럼 **체계와 무관한 수치**는 그대로 표시
- 하위 호환 별칭 `KMA_WEATHER_CODES`는 남겼으나 **신규 코드에서 미사용**
  (테스트도 `KMA_SKY_WEATHER_CODES`로 전환)

### 2.3 WMO 표는 공식 문서에서 그대로 옮겼다

P0-3에서 KMA 표는 "대조하지 않았다"고 정직하게 적어뒀습니다.
이번 WMO 표는 다릅니다 — Open-Meteo 공식 문서 `WMO Weather interpretation codes (WW)` 표에서
**28개 항목을 그대로 옮겼습니다(2026-10 확인)**. 따라서 대조가 가능합니다.

| 코드 | 라벨 | 코드 | 라벨 |
| :--- | :--- | :--- | :--- |
| 0 / 1 / 2 / 3 | 맑음 / 대략 맑음 / 부분적 흐림 / 흐림 | 45 / 48 | 안개 / 서리 안개 |
| 51 / 53 / 55 | 약한·보통·강한 이슬비 | 56 / 57 | 얼어붙는 이슬비 |
| **61 / 63 / 65** | **약한 비 / 비 / 폭우** | 66 / 67 | 얼어붙는 비 |
| **71 / 73 / 75** | **약한 눈 / 눈 / 대설** | 77 | 눈 알갱이 |
| **80 / 81 / 82** | **약한·보통·강한 소나기 비** | 85 / 86 | 소나기 눈 |
| **95 / 96 / 97 / 99** | **천둥번개 / 우박 동반 천둥 / 강한 천둥 / 강한 우박 천둥** | | |

**KMA SKY 표는 여전히 미검증 상태**입니다(§7).

## 3. 수집기가 지켜야 할 원칙 4가지

### 3.1 천문 정보를 잃지 않는다 (자체 감사에서 발견)

첫 구현은 예보 JSON에서 기상 필드만 채워 넣었습니다. 결과:

```
수 · 맑음 강수확률 0% 시간당 0mm 22도 ·  · 16시
                                  ^^^^
        주간길이·절기·일몰이 사라짐 (빈 문자열)
```

Open-Meteo는 절기·일몰·주간길이를 주지 않습니다. 기상만 채워 넣고 나머지를 비우면
**P0-1이 만든 정보가 사라져 기존 출력보다 오히려 약해집니다.**

수정: 천문 신호를 먼저 깔고 그 **위에** 기상 필드만 덮어씁니다(병합, 교체 아님).

```
수 · 맑음 강수확률 0% 시간당 0mm 22도 · 11시간 35분 · 추분 · 일몰 18:19 · 16시
```

### 3.2 실패를 숨기지 않는다

| 실패 | 결과 |
| :--- | :--- |
| 모르는 지역 | FAILED — "좌표를 모릅니다: '제주도 서귀포시'. 알려진 지역: ..." |
| 네트워크 장애 | FAILED — "요청 실패 (URLError). 수집 실패를 값으로 대체하지 않음." |
| HTTP 오류 | FAILED — "HTTP 429 (Too Many Requests)..." |
| JSON 아님 | FAILED — "응답이 JSON이 아닙니다." |
| 시간대 없음 | FAILED |

모의 데이터로 대체하는 경로는 **존재하지 않습니다**. 게다가 `weather_code`를 알아맞추려고
좌표를 추측하지도 않습니다 — 모르면 모른다고 말합니다.

### 3.3 API 키가 감사 장부에 새지 않는다

```python
request_target=url.split("&apikey=")[0]  # 장부에서 키 제거
```

`CollectionProvenance`는 사장님에게도 보일 수 있는 기록입니다.
키가 그 안에 있으면 **장부 자체가 유출 지점**이 됩니다.
서버 호출 URL에는 키가 실리고, 장부·로그에는 남지 않습니다.

### 3.4 퍼센트를 스키마 범위로 정규화

스키마는 `precip_prob: 0~1`, API는 `%`(0~100)입니다. 변환을 빠뜨리면 `80`이 들어가고,
그 값으로 비교하는 문턱 로직이 전부 무력화됩니다. 테스트로 고정했습니다.

## 5. 실측 기상이 전략까지 흐르는 것 확인

```python
plan = AIMPlatform.plan_campaign(tenant.business_state, env_signal=sig)

situation: 오늘 오후 15시 비 예보 + 2시 이후 사워도우 조기 품절 · 수 · 맑음 강수확률 0%
          시간당 0mm 22도 · 11시간 35분 · 추분 · 일몰 18:19 · 16시
objective: CAPACITY_RESCUE | 예상매출: 240,000원
```

**이 출력이 §7.1의 버그를 그대로 드러냅니다.** 실측은 "맑음 강수확률 0%"인데
`objective`가 여전히 `CAPACITY_RESCUE`인 이유는, 사람이 쓴 문자열 "비 예보"에 `비`가 들어 있고
`FnbDomainPlugin`이 부분일치로 그것을 잡기 때문입니다. P0-3 문서에 적어둔 잠재 버그가
실제 운영 경로에서 그대로 재현됩니다. 이번 스텝은 수집기 범위이므로 고치지 않고 §7에 유지합니다.
