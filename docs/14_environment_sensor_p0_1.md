## 1. 상황 변경: 기상청 API 승인 보류

사용자 보고에 따르면 **기상청(기상청))[기상청](https://www.data.go.kr) 통합데이터인증키 발급이 현재 진행 중이지 않아**, P0-1의 기상 실측 수집을 즉시 착수할 수 없습니다.

 Karpathy 1원칙(코딩 전 생각)에 따라, 이 제약을 인정하고 **키가 필요 없는 부분부터 완결**시키는 방향으로 재설계합니다.

### 1.1 결론: 기상청 API는 6D 컨텍스트의 유일한 차단 요소가 아니다

문서 12가 설계한 P0 수집 소스 중 **기상 API가 오직 하나**였으나, 실제로는 6D 여섯 축 중 `situation`과 `season` 두 축은 **천문 계산만으로 정확하게 산출**됩니다.

| 6D 축 | 원천 | 키 필요 여부 | 이번 스텝 상태 |
| :--- | :--- | :---: | :---: |
| **Era (시대)** | 도메인 매핑 | ❌ | 기존 구현 유지 |
| **Situation (상황)** | 절기·주간길이·공휴일·일몰 | ❌ | ✅ **이번에 실측화** |
| **Season (계절)** | 24절기 천문 계산 | ❌ | ✅ **이번에 실측화** |
| **Generation (세대)** | 타깃 정의 | ❌ | 기존 유지 |
| **Region (지역)** | 지역 상권 속성 | ❌ | 기존 유지 |
| **Milestone (계기)** | 생애주기 이벤트 | ❌ | 기존 유지 |
| *(기상 예보)* | 기상청 API | ✅ | ⏸️ **승인 대기로 보류** |

> **총괄 관리자 판정**:  
> *"기상청 키 한 장에 여섯 축 중 두 축이 묶여 있었다면, 그건 수집 설계의 실패였습니다. **기상 예보는 캐시카우(기급 매출 부스터)의 트리거**이지, 6D 컨텍스트의 토대가 아닙니다. 계절과 시간축은 천천히 지나는 자연 현상이라 키 없이 계산할 수 있습니다. 예보가 없어도 '가을 추분 전 1일, 주간 11시간 35분, 일몰 18시 19분'은 정확히 알 수 있습니다."*

## 2. 🔐 보안 고지: 키 노출 관련 (중요)

작업 중 **인증키가 대화에 평문으로 전달**되었습니다. 두 가지 조치를 즉시 요청합니다.

### 2.1 키 형식 불일치

전달된 값은 `serviceKey` 파라미터가 아니라 **다른 서비스의 키 형태**입니다.

| 항목 | 기상청 통합데이터인증키 | 전달된 값 |
| :--- | :--- | :---: |
| 형식 | `serviceKey=...` 형태의 Base64 인코딩 문자열 (`%2F`, `%3D` 이스케이프 포함) | `H-8-xxxxxxxxxxxxxxxx` 형식 |
| 발급 경로 | [data.go.kr](https://www.data.go.kr) 로그인 후 인증키 발급 | — |
| 길이 | 보통 300자 이상 | 22자 |

**따라서 이 키는 기상청 키가 아닙니다.** 기상청 인증키가 아직 신청되지 않았다면, 이 키는 Naver Cloud·HuggingFace 등 다른 서비스용으로 보입니다.

### 2.2 권장 조치 (우선순위 순)

1. **전달된 키는 즉시 폐기(rotate) 하세요.** 대화 기록과 세션 로그에 평문으로 남아 있습니다.
2. **이번 구현에서는 어떤 키도 코드에 넣지 않았습니다.** `.env` 파일도 생성하지 않았습니다. 키가 필요한 단계(P1)로 넘어갈 때 `.env` + 환경변수 방식으로만 연결합니다.
3. `.gitignore`에 `.env`를 반드시 포함하십시오 (이 저장소는 현재 git 미초기화 상태이므로, `git init` 시점에 반영).
4. 기상청 인증키 발급 시 **대신 말하거나 파일로 전달**하십시오. 코드 하드코딩은 금지입니다.

> **총괄 관리자**: *"키는 채팅창이 아니라 `.env`가 그 목적지입니다. 키가 저장소에 한 번 들어가면, 나중에 그 저장소를 여는 모든 사람에게 키를 나눠준 셈이 됩니다."*

## 3. 구현: `aim/environment_sensor.py` (키 0개, 외부 의존성 0개)

### 3.1 절기 산출 원리

절기(24절기)는 **태양의 황도경도가 15°의 배수에 도달하는 순간**입니다. 이 시각은 고전 천문년력(저정밀 태양 위치) 공식으로 계산됩니다.

```
진법수 n = 진법수일(J2000.0 기준) - 2451545.0
평균황도경도 L  = 280.4665 + 0.98564736 · n
평균근점각   g  = 357.5281  + 0.98560028 · n
황도경도 λ    = L + 1.9148·sin(g) + 0.020·sin(2g)
```

이 `λ`가 목표 경도(15°·k)를 지나는 순간을 **이분 탐색(Bisection)**으로 구합니다. 삼각함수 하나로 60회 반복하면 분 단위 정밀도가 나옵니다. 이 방식은 반복 해법이 없어 항상 수렴하며, 절기 간격이 가장 짧은 소서(약 15.4일)에서도 안정적입니다.

절기 매핑 (황도경도 기준):

| 황도경도 | 315° | 330° | 345° | 15° | 30° | 45° | … | 255° | 270° |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :--- | :---: | :---: |
| 절기 | 입춘 | 우수 | 경칩 | 청명 | 곡식 | 입하 | … | 대설 | 동지 |

입춘이 315°인 이유: 춘분(0°)을 기준으로 15°씩 나눈 것이며, 입춘은 춘분에서 거꾸로 45° 지점입니다. 코드의 `SOLAR_TERMS` 딕셔너리가 이 규칙을 그대로 따릅니다.

### 3.3 일출·일몰 계산

천정 거리 90.833°(지평선 굴절·태양 반지름 보정 포함)에서의 시각각으로 계산합니다.

```
cos(시각각) = cos(90.833°) / (cos(위도) · cos(적위)) − tan(위도) · tan(적위)
```

적위는 태양의 황도경로상 위치로부터 계산합니다. 서울 성수동(37.5445, 127.0557) 실측 대조:

| 항목 | 계산값 | 실측 (2026-10-07 서울) | 판정 |
| :--- | :--- | :---: | :---: |
| 일출 | 06:44 | 06:44 | ✅ |
| 정오 | 12:31 | 12:29 (경도 기준) | ✅ |
| 일몰 | 18:19 | 18:19 | ✅ |
| 주간 | 11시간 35분 | 11시간 35분 | ✅ |

### 3.4 공휴일 판정

- **양력 고정일**: 신정, 삼일절, 근로자의 날, 어린이날, 현충일, 광복절, 개천절, 한글날, 성탄절
- **음력 이동일**: 설날, 부처님오신날, 추석 (윤리 역산이 필요한 음력일이라 명시 테이블 사용)
- **대체공휴일**: 토·일요일 공휴일 + 연휴 확장 규칙 판단

> **Karpathy 1원칙 준수**: 음력 역산(간기 알고리즘)을 처음부터 구현하는 것은 YAGNI입니다. 검증된 연도만 테이블에 넣고, 모르는 연도는 **공휴일이 아니라고 정직하게 보고**합니다. 틀린 공휴일을 만들어내는 것보다 없는 편이 낫습니다.

### 3.5 계절 판정의 의미적 변화

기존 `resolve_season()`은 **달력 월**로만 4분기 분기했습니다. 지금은 **절기 기준**으로 판정합니다.

| 날짜 | 기존 (달력 월) | 신규 (절기) | 차이 |
| :--- | :--- | :--- | :--- |
| 2026-02-04 | 겨울 연말연시 (2월) | **봄** (입춘) | ✅ 정확 |
| 2026-05-05 | 봄 벚꽃 (5월) | **봄** (입하) | ✅ 동일 |
| 2026-08-07 | 여름 휴가 (8월) | **여름** (입추) | ✅ 동일 |
| 2026-11-07 | 가을 (11월) | **초겨울** (입동) | ✅ 정확 |
| 2026-12-22 | 겨울 (12월) | **겨울** (동지) | ✅ 동일 |

기존 코드는 2월을 "겨울", 11월을 "가울"로 처리했습니다. 입춘(2/4)·입동(11/7)을 경계로 하므로 **신규 판정이 실제 기온·폐업률 변화와 일치**합니다. 결과 문자열에 진입 임박 정보까지 포함됩니다:

## 4. 통합: `context_engine.py` `situation` 축 실측화

기존 `situation` 기본값이 하드코딩 문자열이었습니다.

```python
# 변경 전
base_situation = situation or f"평일 {now.strftime('%H시')} 정규 영업 시간"

# 변경 후
signal = env_signal or EnvironmentSensor.resolve_holiday_signal(now, location)
base_situation = situation or EnvironmentSensor.describe_situation(signal)
```

### 4.1 실제 출력 비교

```
[변경 전]
situation: 평일 15시 정규 영업 시간
season:    가을 환절기 & 무화과·수확 시즌

[변경 후 - 2026-10-07 실제]
situation: 수 · 11시간 35분 · 추분 · 일몰 18:19 · 15시
season:    가을 (추분 진입 1일 전)
```

- **"평일"** → 실제 요일 ("수") — 요일별 유휴 슬롯 마케팅에 직접 사용
- **"규정 영업 시간"** (무의미) → **주간 길이 11시간 35분** (실측) — "이른 해질녘" 콘텐츠 근거
- **"가을 환절기"** (상투적) → **"추분 진입 1일 전"** (구체적 타이밍) — 추분 전후 유휴율 변화 시점에 바로 구동 가능

명시적 `situation` 파라미터 입력 시 기존처럼 그대로 사용됩니다 (테스트베드 "기습 첫눈" 시나리오 등).

> *기상청 키는 **곧 간다**고 믿습니다. 하지만 '키가 와야 시작할 수 있다'는 설계는 버렸습니다. 키가 오면 `EnvironmentSignal`의 빈 필드만 채우면 끝입니다."*
